Módulo

8. Administración de la Plataforma

Actor Principal

Administrador

Actores Secundarios

Ninguno

Descripción

Permite al Administrador consultar el listado completo de todos los usuarios registrados en la plataforma, con información básica de cada cuenta, para realizar labores de gestión y supervisión.

Prioridad

Alta

Frecuencia de Uso

Frecuente

Precondiciones

  1. El Administrador debe estar autenticado con rol de administrador.
  2. El Administrador debe tener permisos de gestión de usuarios.

Flujo Principal

  1. El Administrador accede al panel de administración.
  2. El Administrador selecciona la sección 'Gestión de usuarios'.
  3. El sistema carga y muestra el listado de todos los usuarios registrados.
  4. Por cada usuario se muestra: nombre, correo, rol, fecha de registro y estado de la cuenta.
  5. El sistema muestra el número total de usuarios registrados en la plataforma.
  6. El Administrador puede navegar entre páginas del listado.
  7. El Administrador puede ordenar el listado por nombre, fecha de registro, rol o estado.
  8. El Administrador puede buscar un usuario específico (UC-AP02).
  9. El Administrador puede seleccionar un usuario para ver su perfil detallado (UC-AP03).

Flujos Alternativos

FA-01: El Administrador puede filtrar el listado por rol (Estudiante, Creador, Administrador).

FA-02: El Administrador puede filtrar por estado de cuenta (activa, suspendida, baneada).

FA-03: El Administrador puede exportar el listado completo en formato CSV para análisis externo.

Flujos de Excepción

FE-01: Si hay error al cargar el listado, el sistema muestra un mensaje e invita a recargar.

FE-02: Si el sistema tiene un número muy elevado de usuarios, pagina los resultados automáticamente para optimizar el rendimiento.

FE-03: Si el Administrador no tiene los permisos necesarios, el sistema redirige a la pantalla de acceso denegado.

Postcondiciones

  1. El Administrador visualiza el listado actualizado de todos los usuarios registrados.
  2. El Administrador puede proceder a gestionar usuarios individuales desde el listado.
  3. El sistema registra el acceso al módulo de gestión en los logs de actividad.

Descripción

Permite al Administrador localizar rápidamente un usuario específico dentro del sistema mediante criterios de búsqueda como nombre, correo electrónico o identificador, para acceder a su perfil y gestionar su cuenta.

Prioridad

Alta

Frecuencia de Uso

Frecuente

Precondiciones

  1. El Administrador debe estar autenticado con rol de administrador.
  2. El Administrador debe estar en la sección de gestión de usuarios.
  3. El Administrador debe conocer al menos un dato del usuario a buscar.

Flujo Principal

  1. El Administrador accede al campo de búsqueda dentro del listado de usuarios.
  2. El Administrador ingresa el criterio de búsqueda: nombre, correo o ID de usuario.
  3. El sistema muestra sugerencias en tiempo real mientras el Administrador escribe.
  4. El Administrador selecciona la sugerencia o presiona buscar.
  5. El sistema filtra el listado y muestra los usuarios que coinciden con el criterio.
  6. El sistema indica el número de resultados encontrados.
  7. El Administrador selecciona un usuario de los resultados para ver su perfil (UC-AP03).

Flujos Alternativos

FA-01: El Administrador puede combinar la búsqueda con filtros adicionales de rol o estado.

FA-02: El Administrador puede buscar por número de teléfono si el usuario lo tiene registrado.

FA-03: El Administrador puede limpiar la búsqueda para volver al listado completo.

Flujos de Excepción

FE-01: Si la búsqueda no arroja resultados, el sistema muestra el mensaje 'No se encontraron usuarios con ese criterio'.

FE-02: Si hay error en el motor de búsqueda, el sistema muestra un mensaje e invita a intentarlo nuevamente.

FE-03: Si el criterio de búsqueda contiene caracteres especiales no permitidos, el sistema los ignora y procesa el resto.

Postcondiciones

  1. El Administrador visualiza los usuarios que coinciden con el criterio de búsqueda.
  2. El Administrador puede acceder al perfil de cualquier usuario encontrado.
  3. El sistema registra la búsqueda en los logs de actividad del Administrador.

Descripción

Permite al Administrador consultar la información completa del perfil de un usuario específico, incluyendo sus datos personales, actividad en la plataforma, compras, cursos y estado de su cuenta.

Prioridad

Alta

Frecuencia de Uso

Frecuente

Precondiciones

  1. El Administrador debe estar autenticado con rol de administrador.
  2. Debe existir el usuario cuyo perfil se desea consultar.
  3. El Administrador debe tener permisos de visualización de perfiles.

Flujo Principal

  1. El Administrador selecciona un usuario desde el listado o resultado de búsqueda.
  2. El sistema carga la vista detallada del perfil del usuario seleccionado.
  3. El sistema muestra los datos personales: nombre, correo, fecha de registro, país y foto de perfil.
  4. El sistema muestra el rol actual del usuario y su estado de cuenta.
  5. El sistema muestra estadísticas del usuario: cursos adquiridos, progreso y actividad reciente.
  6. Si el usuario es Creador, el sistema muestra sus cursos publicados e ingresos generados.
  7. El Administrador puede acceder al historial de actividad del usuario (UC-AP04).
  8. El Administrador puede gestionar el rol del usuario (UC-AP07).
  9. El Administrador puede suspender o banear la cuenta (UC-AP05).
  10. El Administrador puede restaurar una cuenta suspendida (UC-AP06).

Flujos Alternativos

FA-01: El Administrador puede ver las transacciones económicas del usuario desde su perfil.

FA-02: El Administrador puede ver las denuncias realizadas o recibidas por el usuario.

FA-03: El Administrador puede enviar una notificación directa al usuario desde su perfil.

Flujos de Excepción

FE-01: Si el usuario fue eliminado del sistema, el Administrador ve un perfil archivado con datos de solo lectura.

FE-02: Si hay error al cargar el perfil, el sistema muestra un mensaje e invita a recargar.

FE-03: Si el Administrador no tiene permisos para ver datos sensibles, el sistema oculta esos campos automáticamente.

Postcondiciones

  1. El Administrador visualiza la información completa del perfil del usuario.
  2. El Administrador puede ejecutar acciones de gestión sobre la cuenta desde esta vista.
  3. El sistema registra el acceso al perfil en los logs de actividad.

Permite al Administrador consultar el registro cronológico completo de las acciones realizadas por un usuario específico en la plataforma, incluyendo inicios de sesión, compras, publicaciones y reportes recibidos.

Prioridad

Media

Frecuencia de Uso

Ocasional

Precondiciones

  1. El Administrador debe estar autenticado con rol de administrador.
  2. El Administrador debe estar visualizando el perfil detallado del usuario.
  3. El usuario debe tener actividad registrada en el sistema.

Flujo Principal

  1. El Administrador accede al perfil detallado del usuario (UC-AP03).
  2. El Administrador selecciona la pestaña 'Historial de actividad'.
  3. El sistema recupera y muestra el registro de actividad del usuario.
  4. El historial se muestra en orden cronológico descendente.
  5. Por cada evento se muestra: tipo de acción, fecha, hora, dispositivo y dirección IP.
  6. El Administrador puede filtrar el historial por tipo de actividad: inicio de sesión, compras, publicaciones o reportes.
  7. El Administrador puede filtrar por rango de fechas.
  8. El Administrador puede expandir un evento para ver más detalles.
  9. El Administrador puede exportar el historial en formato PDF o CSV si es necesario para investigación.

Flujos Alternativos

FA-01: El Administrador puede marcar eventos sospechosos para seguimiento.

FA-02: El Administrador puede ver el historial de sesiones activas del usuario.

FA-03: Si el usuario es Creador, el historial incluye acciones sobre sus cursos publicados.

Flujos de Excepción

FE-01: Si el usuario no tiene actividad registrada en el período seleccionado, el sistema muestra un mensaje informativo.

FE-02: Si hay error al cargar el historial, el sistema muestra un mensaje e invita a recargar.

FE-03: Si el historial es muy extenso, el sistema lo pagina para optimizar el rendimiento.

Postcondiciones

  1. El Administrador visualiza el historial de actividad completo del usuario.
  2. El Administrador puede tomar decisiones fundamentadas sobre la gestión de la cuenta.
  3. El sistema registra el acceso al historial en los logs de auditoría.

Descripción

Permite al Administrador restringir el acceso de un usuario a la plataforma de forma temporal (suspensión) o permanente (baneo), como medida disciplinaria ante el incumplimiento de las políticas de uso de GastroGuide.

Prioridad

Alta

Frecuencia de Uso

Poco frecuente

Precondiciones

  1. El Administrador debe estar autenticado con rol de administrador.
  2. El Administrador debe estar visualizando el perfil del usuario a sancionar.
  3. El Administrador debe haber revisado la evidencia que justifica la acción.
  4. La cuenta del usuario debe estar en estado activo.

Flujo Principal

  1. El Administrador accede al perfil detallado del usuario (UC-AP03).
  2. El Administrador selecciona la opción 'Suspender usuario' o 'Banear usuario'.
  3. El sistema muestra el formulario de confirmación de la acción.
  4. El Administrador selecciona el motivo de la sanción de la lista predefinida.
  5. El Administrador puede agregar una descripción adicional del motivo.
  6. Si es suspensión, el Administrador define la duración (días, semanas o tiempo indefinido).
  7. El Administrador confirma la acción.
  8. El sistema aplica la sanción y cambia el estado de la cuenta.
  9. El sistema cierra todas las sesiones activas del usuario inmediatamente.
  10. El sistema envía una notificación al usuario informando la sanción y su motivo.
  11. El sistema registra la acción en los logs con fecha, hora y Administrador responsable.

Flujos Alternativos

FA-01: El Administrador puede suspender múltiples usuarios de forma masiva si hay una situación que lo requiera.

FA-02: Si el usuario sancionado es Creador, el sistema oculta sus cursos del catálogo durante la suspensión.

FA-03: El sistema puede enviar automáticamente una advertencia previa antes de aplicar la suspensión si es la primera infracción.

Flujos de Excepción

FE-01: Si el Administrador intenta suspender a otro Administrador, el sistema requiere confirmación de un superadministrador.

FE-02: Si el usuario tiene transacciones pendientes de procesar, el sistema advierte antes de aplicar el baneo.

FE-03: Si hay error al aplicar la sanción, el sistema no modifica el estado de la cuenta y muestra un mensaje de error.

Postcondiciones

  1. La cuenta del usuario queda en estado suspendido o baneado.
  2. Todas las sesiones activas del usuario son cerradas inmediatamente.
  3. El usuario recibe una notificación con el motivo y duración de la sanción.
  4. Los cursos del Creador sancionado quedan ocultos del catálogo durante la suspensión.
  5. La acción queda registrada en los logs de auditoría.

Descripción

Permite al Administrador levantar la suspensión de una cuenta de usuario, restaurando su acceso completo a la plataforma cuando la sanción ha cumplido su período o se ha resuelto la situación que la originó.

Prioridad

Media

Frecuencia de Uso

Poco frecuente

Precondiciones

  1. El Administrador debe estar autenticado con rol de administrador.
  2. La cuenta del usuario debe estar en estado suspendido.
  3. El Administrador debe estar visualizando el perfil del usuario suspendido.

Flujo Principal

  1. El Administrador accede al perfil del usuario con cuenta suspendida (UC-AP03).
  2. El sistema muestra el estado de suspensión con el motivo y la fecha de aplicación.
  3. El Administrador selecciona la opción 'Restaurar cuenta'.
  4. El sistema muestra el formulario de confirmación de restauración.
  5. El Administrador ingresa el motivo de la restauración.
  6. El Administrador confirma la acción.
  7. El sistema cambia el estado de la cuenta a activo.
  8. El sistema reactiva los cursos del Creador en el catálogo si aplica.
  9. El sistema notifica al usuario que su cuenta ha sido restaurada.
  10. El sistema registra la restauración en los logs con fecha, hora y Administrador responsable.

Flujos Alternativos

FA-01: El sistema puede restaurar automáticamente las cuentas suspendidas temporalmente cuando vence el período de suspensión.

FA-02: El Administrador puede agregar una advertencia formal al restaurar la cuenta indicando que una nueva infracción resultará en baneo permanente.

FA-03: El Administrador puede restaurar parcialmente una cuenta permitiendo acceso de solo lectura antes de la restauración completa.

Flujos de Excepción

FE-01: Si la cuenta está baneada permanentemente, el sistema no permite restaurarla sin autorización de un superadministrador.

FE-02: Si hay error al restaurar la cuenta, el sistema mantiene el estado suspendido y notifica al Administrador.

FE-03: Si el usuario baneado tiene apelaciones activas en proceso, el sistema lo indica al Administrador antes de confirmar la restauración.

Postcondiciones

  1. La cuenta del usuario queda en estado activo y puede acceder nuevamente a la plataforma.
  2. Los cursos del Creador restaurado vuelven a ser visibles en el catálogo.
  3. El usuario recibe notificación de que su cuenta ha sido reactivada.
  4. La restauración queda registrada en los logs de auditoría.

Descripción

Permite al Administrador modificar el rol asignado a un usuario de la plataforma, por ejemplo promoviendo un Estudiante a Creador, o revocando permisos de Creador a un usuario que incumple las políticas.

Prioridad

Alta

Frecuencia de Uso

Ocasional

Precondiciones

  1. El Administrador debe estar autenticado con rol de administrador.
  2. El Administrador debe estar visualizando el perfil detallado del usuario.
  3. El usuario debe tener una cuenta activa y verificada.

Flujo Principal

  1. El Administrador accede al perfil detallado del usuario (UC-AP03).
  2. El Administrador selecciona la opción 'Gestionar roles y permisos'.
  3. El sistema muestra el rol actual del usuario y las opciones disponibles.
  4. El Administrador selecciona el nuevo rol a asignar.
  5. El sistema muestra un resumen de los permisos que conlleva el nuevo rol.
  6. El Administrador confirma el cambio de rol.
  7. El sistema actualiza el rol del usuario en la base de datos.
  8. El sistema actualiza los permisos de acceso del usuario de forma inmediata.
  9. El sistema notifica al usuario del cambio de rol.
  10. El sistema registra la acción en los logs de auditoría.

Flujos Alternativos

FA-01: Si se asigna el rol de Creador, el sistema verifica que el usuario haya completado el proceso de verificación de identidad.

FA-02: El Administrador puede asignar permisos específicos adicionales sin cambiar el rol base del usuario.

FA-03: Si se revoca el rol de Creador, el sistema archiva los cursos publicados del usuario y lo notifica.

Flujos de Excepción

FE-01: Si el usuario no cumple los requisitos para el nuevo rol (p.ej. cuenta no verificada), el sistema bloquea el cambio e indica los requisitos faltantes.

FE-02: Si hay error al actualizar el rol, el sistema mantiene el rol anterior y notifica al Administrador.

FE-03: Si el Administrador intenta modificar el rol de otro Administrador, el sistema requiere autorización de nivel superior.

Postcondiciones

  1. El usuario tiene asignado el nuevo rol con sus permisos correspondientes.
  2. Los cambios de acceso son efectivos de forma inmediata.
  3. El usuario recibe notificación del cambio de rol.
  4. El cambio queda registrado en los logs de auditoría con el Administrador responsable.

Permite al Administrador consultar la información completa y detallada de un curso específico desde la perspectiva administrativa, incluyendo su estructura, métricas, historial de denuncias y opciones de gestión disponibles.

Prioridad

Alta

Frecuencia de Uso

Frecuente

Precondiciones

  1. El Administrador debe estar autenticado con rol de administrador.
  2. El Administrador debe haber seleccionado un curso desde el listado o resultado de búsqueda.

Flujo Principal

  1. El Administrador selecciona un curso desde el listado o búsqueda.
  2. El sistema carga la vista de administración del curso seleccionado.
  3. El sistema muestra la información general: título, descripción, creador, categoría, precio y fecha de publicación.
  4. El sistema muestra la estructura del curso: módulos, lecciones y recursos.
  5. El sistema muestra las métricas del curso: estudiantes inscritos, calificación promedio, tasa de finalización e ingresos generados.
  6. El sistema muestra el historial de denuncias recibidas por el curso si las hay.
  7. El Administrador puede revisar el contenido denunciado (UC-AP11).
  8. El Administrador puede eliminar el curso si viola las políticas (UC-AP12).
  9. El Administrador puede destacar el curso en la página principal.

Flujos Alternativos

FA-01: El Administrador puede ver el curso tal como lo ven los estudiantes usando la vista previa.

FA-02: El Administrador puede contactar al Creador directamente desde el detalle del curso.

FA-03: El Administrador puede ver el historial de actualizaciones del curso.

Flujos de Excepción

FE-01: Si hay error al cargar el detalle del curso, el sistema muestra un mensaje e invita a recargar.

FE-02: Si el curso fue archivado mientras el Administrador lo visualizaba, el sistema actualiza el estado automáticamente.

FE-03: Si el Administrador no tiene permisos para ver datos financieros del curso, esos campos se ocultan.

Postcondiciones

  1. El Administrador visualiza la información completa del curso.
  2. El Administrador puede ejecutar acciones de gestión sobre el curso desde esta vista.
  3. El sistema registra el acceso al detalle del curso en los logs de actividad.

Descripción

Permite al Administrador revisar y evaluar las denuncias realizadas por usuarios sobre cursos, lecciones o comentarios que presuntamente incumplen las políticas de uso de la plataforma, para tomar la acción correspondiente.

Prioridad

Alta

Frecuencia de Uso

Frecuente

Precondiciones

  1. El Administrador debe estar autenticado con rol de administrador.
  2. Debe existir al menos una denuncia pendiente de revisión en el sistema.
  3. El Administrador debe tener acceso al módulo de moderación de contenido.

Flujo Principal

  1. El Administrador accede al módulo de moderación de contenido.
  2. El sistema muestra el listado de denuncias pendientes ordenadas por urgencia y fecha.
  3. El Administrador selecciona una denuncia para revisar.
  4. El sistema muestra los detalles: contenido denunciado, motivo de la denuncia, usuario denunciante y fecha.
  5. El Administrador accede al contenido denunciado para evaluarlo.
  6. El Administrador evalúa si el contenido viola las políticas de la plataforma.
  7. El Administrador selecciona la acción: desestimar denuncia, emitir advertencia al creador, o eliminar contenido (UC-AP12).
  8. El sistema ejecuta la acción seleccionada.
  9. El sistema notifica al usuario denunciante sobre la resolución.
  10. El sistema notifica al Creador del contenido sobre la decisión tomada.
  11. El sistema registra la resolución en los logs de auditoría.

Flujos Alternativos

FA-01: El Administrador puede escalar una denuncia a un nivel superior si requiere revisión adicional.

FA-02: El Administrador puede ver el historial de denuncias previas del mismo Creador para contextualizar la decisión.

FA-03: El Administrador puede marcar contenido como 'En revisión' mientras evalúa antes de tomar una decisión final.

Flujos de Excepción

FE-01: Si el contenido denunciado ya fue eliminado por el Creador antes de la revisión, el sistema cierra automáticamente la denuncia.

FE-02: Si hay error al cargar el contenido denunciado, el sistema muestra un mensaje e invita a recargar.

FE-03: Si la denuncia ya fue resuelta por otro Administrador, el sistema lo indica y muestra la resolución tomada.

Postcondiciones

  1. La denuncia queda resuelta con la acción correspondiente registrada.
  2. El usuario denunciante recibe notificación sobre el resultado de su denuncia.
  3. El Creador recibe notificación si su contenido fue sancionado.
  4. La resolución queda registrada en los logs de auditoría.

Descripción

Permite al Administrador eliminar permanentemente un curso de la plataforma cuando este incumple gravemente las políticas de uso, garantizando la comunicación adecuada al Creador y la gestión de los estudiantes afectados.

Prioridad

Alta

Frecuencia de Uso

Poco frecuente

Precondiciones

  1. El Administrador debe estar autenticado con rol de administrador.
  2. El Administrador debe estar visualizando el detalle del curso a eliminar.
  3. Debe existir evidencia documentada que justifique la eliminación del curso.
  4. El Administrador debe haber revisado el contenido y la denuncia asociada.

Flujo Principal

  1. El Administrador accede al detalle del curso (UC-AP10).
  2. El Administrador selecciona la opción 'Eliminar curso'.
  3. El sistema muestra un formulario de confirmación con el impacto de la acción.
  4. El sistema informa el número de estudiantes inscritos que se verán afectados.
  5. El sistema informa el número de transacciones activas asociadas al curso.
  6. El Administrador selecciona el motivo de la eliminación.
  7. El Administrador puede agregar una descripción detallada del motivo.
  8. El Administrador confirma la eliminación.
  9. El sistema retira el curso del catálogo inmediatamente.
  10. El sistema revoca el acceso de todos los estudiantes inscritos.
  11. El sistema procesa los reembolsos automáticos a los estudiantes afectados.
  12. El sistema notifica al Creador con el motivo de la eliminación.
  13. El sistema notifica a los estudiantes inscritos sobre la eliminación y el reembolso.
  14. El sistema registra la acción en los logs de auditoría con todos los detalles.

Flujos Alternativos

FA-01: El Administrador puede suspender temporalmente el curso en lugar de eliminarlo si el Creador puede corregir las infracciones.

FA-02: Si el Creador tiene otros cursos activos, el sistema evalúa si también deben ser revisados.

FA-03: El Administrador puede ofrecer al Creador un período de apelación antes de ejecutar la eliminación definitiva.

Flujos de Excepción

FE-01: Si hay transacciones en proceso al momento de la eliminación, el sistema espera a que se completen antes de procesar los reembolsos.

FE-02: Si el procesamiento de reembolsos falla, el sistema marca las transacciones para revisión manual.

FE-03: Si hay error durante la eliminación, el sistema revierte todos los cambios y mantiene el curso en su estado anterior.

Postcondiciones

  1. El curso queda eliminado y no es visible en ninguna parte de la plataforma.
  2. Los estudiantes inscritos pierden el acceso y reciben reembolso si aplica.
  3. El Creador y los estudiantes reciben notificación con el motivo de la eliminación.
  4. La eliminación queda registrada permanentemente en los logs de auditoría.

Prioridad

Alta

Frecuencia de Uso

Frecuente

Precondiciones

  1. El Administrador debe estar autenticado con rol de administrador.
  2. El Administrador debe haber seleccionado un curso desde el listado de cursos pendientes.
  3. El curso debe estar en estado 'Pendiente de revisión'.

  1. El Administrador selecciona un curso pendiente desde el listado (UC-AP13).
  2. El sistema muestra el contenido completo del curso para su revisión.
  3. El Administrador revisa el título, descripción, imagen de portada y categoría del curso.
  4. El Administrador revisa los módulos y lecciones del curso verificando calidad del contenido.
  5. El Administrador verifica que el precio y modelo de acceso estén correctamente configurados.

FA-03: Si el Creador es verificado con historial positivo, el sistema puede sugerir aprobación automática.

Flujos de Excepción

FE-01: Si el video de alguna lección no ha terminado de procesarse, el sistema advierte al Administrador antes de aprobar.

FE-02: Si hay error al cambiar el estado del curso, el sistema mantiene el estado anterior y notifica al Administrador.

FE-03: Si el Creador modificó el curso mientras estaba en revisión, el sistema notifica al Administrador sobre los cambios realizados.

Postcondiciones

  1. Si fue aprobado: el curso queda publicado y visible en el catálogo para todos los usuarios.
  2. Si fue rechazado: el curso vuelve al estado de borrador con los comentarios del Administrador.
  3. El Creador recibe notificación con la decisión y los motivos correspondientes.
  4. La decisión queda registrada en los logs de auditoría.

Alta

Continua

FA-03: El sistema puede generar reportes automáticos de rendimiento diarios o semanales.

FE-01: Si el Sistema de Monitoreo deja de funcionar, el sistema activa un monitoreo de respaldo y alerta al equipo técnico.

FE-02: Si los valores de las métricas son anómalos, el sistema los marca para revisión antes de generar alertas falsas.

FE-03: Si hay error al cargar el dashboard, el sistema muestra los últimos datos disponibles con una marca de tiempo.

Postcondiciones

  1. El Administrador tiene visibilidad en tiempo real del estado operativo de la plataforma.
  2. Las métricas quedan almacenadas para análisis histórico.
  3. El sistema genera alertas automáticas ante situaciones que requieren intervención.
  4. El Administrador puede tomar decisiones informadas sobre la infraestructura.

Descripción

Permite al Sistema de Monitoreo ejecutar automáticamente los procesos de respaldo de datos de la plataforma y al Administrador gestionar las copias de seguridad y ejecutar procesos de recuperación ante situaciones de pérdida de datos o fallos críticos.

Prioridad

Alta

Frecuencia de Uso

Continua (automático) / Ocasional (manual)

Precondiciones

  1. El sistema de backups debe estar configurado y operativo.
  2. El Administrador debe estar autenticado con rol de administrador para acciones manuales.
  3. Debe existir suficiente espacio de almacenamiento para las copias de seguridad.

Flujo Principal

  1. El sistema ejecuta automáticamente los backups según el calendario configurado.
  2. El sistema realiza backups incrementales diarios y backups completos semanales.
  3. El sistema almacena las copias en ubicaciones redundantes (local y nube).
  4. El sistema verifica la integridad de cada backup generado.
  5. El sistema registra el resultado del backup en el log de operaciones.
  6. El Administrador accede al panel de gestión de backups.
  7. El sistema muestra el listado de backups disponibles con fecha, tamaño e integridad.
  8. El Administrador puede iniciar un backup manual si la situación lo requiere.
  9. En caso de fallo, el Administrador puede iniciar el proceso de recuperación seleccionando el punto de restauración.
  10. El sistema ejecuta la recuperación y notifica al Administrador sobre el resultado.

Flujos Alternativos

FA-01: El Administrador puede configurar la frecuencia y tipo de backups desde el panel.

FA-02: El sistema puede eliminar automáticamente los backups más antiguos cuando se alcanza el límite de almacenamiento.

FA-03: El Administrador puede descargar un backup específico para revisión o migración.

Flujos de Excepción

FE-01: Si un backup falla, el sistema notifica al Administrador inmediatamente y reintenta automáticamente.

FE-02: Si la integridad de un backup está comprometida, el sistema lo marca como inválido y genera uno nuevo.

FE-03: Si el proceso de recuperación falla, el sistema detiene la operación y preserva el estado actual para evitar mayor pérdida de datos.

Postcondiciones

  1. Los datos de la plataforma quedan respaldados de forma segura y verificada.
  2. El historial de backups queda registrado con fecha, tipo e integridad.
  3. En caso de recuperación, los datos quedan restaurados al punto de restauración seleccionado.
  4. El Administrador recibe confirmación del resultado de cada operación de backup o recuperación.
